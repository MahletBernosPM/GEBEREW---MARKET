## Overview

The database is a PostgreSQL instance with the PostGIS extension enabled.  
It stores 7 core tables. Row Level Security (RLS) is enabled on every user-facing table so that the database enforces access rules even if the API layer has a bug.

---

## Tables

### `users`
Stores all accounts — farmers, buyers, cooperatives, operators, and admins.  
Phone number is the primary login identifier. Email/password is for internal operators only (handled at the application layer).

| Column | Type | Notes |
|---|---|---|
| `id` | `TEXT` PK | UUID generated by the app |
| `phone` | `TEXT` UNIQUE | Primary identifier for OTP auth |
| `role` | `Role` enum | `FARMER`, `BUYER`, `COOPERATIVE`, `OPERATOR`, `ADMIN` |
| `assigned_region` | `TEXT` nullable | Set for `OPERATOR` accounts only — scopes their RLS access |
| `created_at` | `TIMESTAMP` | Auto |
| `updated_at` | `TIMESTAMP` | Auto |

### `crops`
Canonical crop registry. Names are stored in all three languages so the frontend can render in Amharic, Afaan Oromoo, or English.

| Column | Type | Notes |
|---|---|---|
| `id` | `TEXT` PK | UUID |
| `name_am` | `TEXT` | Amharic name (e.g. ጤፍ) |
| `name_om` | `TEXT` | Afaan Oromoo name (e.g. Xaafii) |
| `name_en` | `TEXT` nullable | English name (e.g. Teff) |
| `created_at` | `TIMESTAMP` | Auto |

Seeded crops: **Teff, Maize, Wheat, Red Onion, Coffee**

### `markets`
Wholesale market locations. The `location` column stores a PostGIS geo-point in WGS-84 (SRID 4326), the same coordinate system used by GPS and Google Maps.

| Column | Type | Notes |
|---|---|---|
| `id` | `TEXT` PK | UUID |
| `name` | `TEXT` | Display name (e.g. "Merkato") |
| `region` | `TEXT` | Region name — used to scope operator RLS |
| `location` | `geometry(Point, 4326)` | GPS coordinates — longitude, latitude |

**Inserting a market with a geo-point:**
```sql
INSERT INTO markets (id, name, region, location)
VALUES (
  'merkato',
  'Merkato',
  'Addis Ababa',
  ST_SetSRID(ST_MakePoint(38.7369, 9.0192), 4326)
);
```

**Querying coordinates back:**
```sql
SELECT name, ST_X(location::geometry) AS lng, ST_Y(location::geometry) AS lat
FROM markets;
```

### `sms_messages`
Full log of every inbound and outbound SMS. Inbound = user texted the short code. Outbound = system sent a price update or digest.

| Column | Type | Notes |
|---|---|---|
| `id` | `TEXT` PK | UUID |
| `user_id` | `TEXT` FK → users, nullable | Linked user if identified, null if unregistered sender |
| `sender` | `TEXT` | Phone number of the sender |
| `direction` | `SmsDirection` enum | `INBOUND` or `OUTBOUND` |
| `intent` | `TEXT` nullable | Parsed command (e.g. "price_query", "listing_create") |
| `response` | `TEXT` | The message content |
| `status` | `TEXT` nullable | Gateway delivery status |
| `cost` | `DECIMAL(8,4)` nullable | Cost in USD per gateway pricing |
| `created_at` | `TIMESTAMP` | Auto |

## Row Level Security (RLS)

RLS is enabled on all 5 user-facing tables. The `crops` and `markets` tables are read-only reference data with no per-user sensitivity, so they use no RLS.

### How the API layer sets context

At the start of every authenticated request, the API must run:

```sql
SET LOCAL app.current_user_id = '<user-uuid>';
SET LOCAL app.current_role    = 'FARMER';     -- or BUYER, COOPERATIVE, OPERATOR, ADMIN
SET LOCAL app.current_region  = 'Oromia';     -- operators only, empty string for others
```

These are session-local variables that Postgres resets after each transaction. RLS policies read them via `current_setting('app.current_role', true)`.

---

### RLS Matrix

| Table | FARMER | BUYER | COOPERATIVE | OPERATOR | ADMIN |
|---|---|---|---|---|---|
| `users` | Own row (R/W) | Own row (R/W) | Own row (R/W) | All rows (R) | All rows (R/W) |
| `crops` | All (R) — no RLS | All (R) | All (R) | All (R) | All (R/W) |
| `markets` | All (R) — no RLS | All (R) | All (R) | All (R) | All (R/W) |
| `prices` | Verified only (R) | Verified only (R) | Verified only (R) | All (R/W) | All (R/W) |
| `listings` | Own (R/W) | Active only (R) | Own (R/W) | Region-scoped (R/W) | All (R/W) |
| `inquiries` | Own listings' inquiries (R) | Own (R/W) | Own (R/W) | Region-scoped (R) | All (R/W) |
| `sms_messages` | Own (R) | Own (R) | Own (R) | All (R) | All (R/W) |

### Policy Details

#### `users` table
- `admin_all_users` — Admin: full access to all rows
- `user_own_profile` — Any role: can SELECT their own row
- `user_update_own_profile` — Any role: can UPDATE their own row
- `operator_read_users` — Operator: can SELECT all rows (needed to resolve farmer contacts)

#### `prices` table
- `admin_all_prices` — Admin: full access
- `operator_all_prices` — Operator: full access (submit + verify prices)
- `public_verified_prices` — Farmer/Buyer/Cooperative: SELECT only where `is_verified = true`

#### `sms_messages` table
- `admin_all_sms` — Admin: full access
- `operator_read_sms` — Operator: SELECT all (delivery health monitoring)
- `user_own_sms` — Any user: SELECT their own messages

#### `listings` table
- `admin_all_listings` — Admin: full access
- `farmer_own_listings` — Farmer: full access to their own listings
- `buyer_active_listings` — Buyer: SELECT only where `status = 'ACTIVE'`
- `cooperative_own_listings` — Cooperative: full access to listings they created
- `operator_region_listings` — Operator: access listings whose linked market is in `app.current_region`

#### `inquiries` table
- `admin_all_inquiries` — Admin: full access
- `farmer_listing_inquiries` — Farmer: SELECT inquiries on their own listings
- `buyer_own_inquiries` — Buyer: full access to their own inquiries
- `cooperative_own_inquiries` — Cooperative: full access to inquiries they created
- `operator_region_inquiries` — Operator: SELECT inquiries linked to listings in their region

## Running Locally

```bash
# Start the PostGIS database (port 5433 — avoids conflict with any local Postgres)
docker compose up -d

# Apply migrations
npx prisma migrate dev

# Seed with crops, markets, and sample prices
npx prisma db seed

# Open Prisma Studio to browse the data visually
npx prisma studio
```
